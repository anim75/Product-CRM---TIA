# Product Growth with Imtial

Open `index.html` to use the responsive, unified platform. For consistent browser storage across pages, serve this directory with `python -m http.server 8080` and open `http://localhost:8080`.

Includes a visual overview, one consolidated Projects workspace, Product timeline, Meeting studio, Campaigns & ROI, Marketing & lifetime, Audience analytics and Settings. Project creation, multiple task entry, editing, status boards, search, priorities and design/reference resources live together. Meeting capture, summary and email review share one guided flow. CSV exports and JSON backup/restore are retained. Example projects, tasks and campaign data are preloaded.

Original numbered URLs remain compatible: product/board/work/situation routes open Projects, Calendar opens Product timeline, and Email opens the compose step in Meeting studio. Work notes, the standalone KPI calculator and standalone Files & links are removed from navigation. Existing stored records are preserved in workspace backups. The original mockups remain in `design-reference/`.

Data is stored in this browser's localStorage. Sign-up and password sign-in are local to this device, not server-backed authentication. Email opens your email application's draft composer. The optional local Node server provides AI meeting summaries when configured; there is no cloud data storage, cross-device synchronization or automatic email sending. Export a backup to transfer your data.

Run `node verify.cjs` for functional smoke checks and KPI formula tests. No dependencies or build step required.

The redesigned interface uses `workspace.js` and `workspace.css` over the existing data layer. Dashboard development health derives from completed tasks, overdue task/project dates and planned work. Projects in motion counts projects with unfinished tasks; completed meetings counts saved meetings dated through today. Revenue charts use recorded daily product metrics rather than campaign totals. Missing data is shown explicitly. Product timeline displays task due dates and project target diamonds; project windows require a start date and target date. Mobile includes a four-item bottom navigation and a full menu for growth reports and settings. Transitions and ambient motion honor reduced-motion preferences.

`experience.js` and `experience.css` add the white/lavender/blue palette and a clean **Product Growth with Imtial** entrance page. A single illustrated product manager and a short introduction sit beside the account form, positioned near the top. The crowded demo tickers and charts are removed. The illustration can be paused and respects reduced-motion preferences. Mobile places a compact introduction and illustration above the form. Fonts are DM Sans and Plus Jakarta Sans, with system fallbacks. Known mojibake from older builds is repaired in the source and in saved workspace text. The main app header shows the platform title without the old dated workspace heading or global Add work item link.

Projects support repeatable team members with names and designations at creation and in the team editor. Task assignee fields suggest the selected project's team names. Project details can be edited, including start and end dates; tasks also store start and end dates. The UI rejects reversed date ranges before saving. Product timeline uses project and task ranges where available, with due-date markers for older records. Team members and dates are included in workspace backups. Adding a member records project context; it does not send an invitation or create a separate user account.

Development health is scored per product phase out of 100: PRD 10, UI/UX / Prototype 20, Frontend development 20, Backend development 20, SEO 15 and UAT 15. New tasks require one of these six work types and have a phase name. Progress controls award Done = 100%, Processing = 50% and Undone = 0%. When a section has multiple tasks, their completion is averaged within the section's weight; missing sections earn zero. For example, SEO processing earns 7.5/15 points. Development phases use Phase 1?10 dropdowns when adding/editing products and tasks. Existing custom phases remain accessible as saved phases so old tasks are preserved. The phase selector switches the board and health breakdown. Existing unclassified tasks remain visible and score zero until a work type is assigned. Project progress and the dashboard health ring use the weighted score; dashboard health shows the selected product at its current phase. `node verify-lifecycle.cjs` checks weights, fractional scores, phase isolation and the 100-point cap.

The interface now uses **Product/Products** terminology throughout; older internal `#projects` links remain compatible. Task assignees are required dropdowns populated only from the selected product's members, showing names and designations. A single member is selected automatically. Add team members before assigning tasks; switching the product refreshes the available names. Existing assignments outside the current team must be reassigned when editing. Task cards have stable numbered names within the product phase and render each task-detail line as a numbered point. A separate **Product health section** dropdown selects the relevant weighted category. Product pages show a circular score out of 100 and all six earned/maximum section bars. The dashboard development-health dropdown selects one product and shows its score circle and six matching parameter bars at its current phase.

**Add tasks & supporting links** is organized into three steps: Task & points; Assign & plan; Links & review. All original fields remain available. Related fields sit side by side on desktop and stack on mobile. Each step validates before continuing, drafts stay in the form when moving backward, and the last step summarizes the tasks before saving with optional design/reference links. Multiple task entry is retained.

The overview hero includes a moving product-health tape, portfolio counts and an animated delivery flow. Product names, phases and six-section health values come from saved workspace records. A product is Upcoming when its start date is in the future or its selected phase has no tasks; otherwise it is Working unless health is 100 (Complete). The small bars show the six current health sections, not historical stock-price trends. Product cards open the relevant product. The carousel pauses on hover/focus, has an explicit pause/resume control, and respects reduced-motion preferences. Duplicate carousel items are excluded from keyboard and screen-reader navigation.

Settings → System color theme offers White (the original lavender/blue appearance), Black, Futuristic blue, Futuristic red, Futuristic purple and Futuristic orange. Selection applies immediately across the workspace and sign-in page, without discarding unsaved profile edits. The preference persists in browser storage and workspace backups; old backups default to White. A small appearance preference is read before styles load to avoid flashing the default theme on reload. Dark palettes change surfaces, text, forms, charts and navigation as well as accents.

`local-auth.js` supports one local account per browser, with name/email/password, confirmation, password visibility and sign-out/sign-in. It stores a random 16-byte salt and a PBKDF2-SHA-256 password hash (210,000 iterations), never a plaintext password. Passwords require 10–128 characters. Account credentials are stored separately from workspace backups. Existing workspace records remain intact when creating a local account. Clearing browser storage removes both data and the local account; there is no email recovery or cross-device login. This is a local access flow, not a security boundary against someone with access to browser storage. Use a real authentication backend before deploying a shared private workspace. Run `node verify-auth.cjs` for account checks.

`node preview-check.cjs` runs real-browser functional and layout checks against a separate headless Chromium profile with DevTools at `127.0.0.1:9223` and the app at `http://localhost:8080`. It covers project/task/resource creation, task edits/status, meeting email generation, all eight mobile routes, page overflow, mobile menu and reduced motion. Its isolated browser storage is reset to example data; never run it against your personal browser profile. Captured desktop and mobile screenshots are saved in `preview/`.

Project situation supports a project dropdown, multiple tasks with bullet-point details, and repeatable design/reference links. Tasks also appear in the existing work board.

Marketing & lifetime stores editable daily metrics per product. Reports cover the last 30 days, last 7 days, or one selected day, with monthly budgets and a separate lifetime tab. Subscriber base and active players use the latest snapshot in the period; CPA uses total cost divided by total GP/BL/Robi onboarding. Lifetime net profit is revenue minus recorded marketing costs, excluding other business expenses. Campaign costs and revenue remain separate from daily records to avoid double counting.

Campaigns include budget, prize details, boost/shoot/PR/vendor/print costs, inclusive start/end dates, operator onboarding, active players, subscriber base and up to ten winners. Analytics includes web visits, social views/interactions/engagements and a visit-weighted average duration. Audience fields record each day's leading age group, location, target group, device and game; they are not full demographic distributions. All new metrics are entered manually and included in JSON workspace backups.

Meeting notes generate an editable email subject and body in the original email design's format: greeting, meeting metadata, summary, decisions, action items, execution timeline, conclusion and the complete Tanjim Imtial / Rangs Babylonia / EDISON GROUP signature. Existing saved meetings can also be prepared in this format. Copy, download, save edits or open an email draft after reviewing.

Local formatting preserves all supplied notes; optional section labels (`Summary:`, `Decisions:`, `Action items:`, `Timeline:`, `Conclusion:`) organize them. This mode does not perform AI summarization. AI mode summarizes through the optional server, retains the original notes, and never silently falls back on an AI failure.

For AI mode, set `OPENAI_API_KEY` and `OPENAI_MODEL` in the server environment (choose a Responses API model that supports structured outputs), then run `node server.cjs` and open `http://localhost:8080/#meetings`. Node 20+ is required; no npm packages are needed. Stop an existing preview server on port 8080 first, or set `PORT` to a different port. Keep using the same hostname/port for existing browser data. Do not place API keys in browser fields or source files. AI generation sends the entered meeting topic, date, attendees and notes to OpenAI; the company signature is appended locally. No meeting data is saved on the Node server. Run `node verify-meetings.cjs` for formatter and mocked AI/server checks.

The overview Revenue & marketing panel shows all-time saved daily metrics through today, grouped by product. A product filter offers all products or a single product. Revenue and marketing spend share a monetary scale; onboarding has a separate people-count scale and GP/BL/Robi breakdown. Summary totals follow the selected filter. Future-dated records and campaign totals are excluded, preventing future projections and duplicate campaign accounting from affecting these bars. Products without daily records remain listed with missing-data labels.

Profile & Google connections
----------------------------
The header avatar opens Profile & password, Settings, Google connections, sign-in and logout. Profile settings offer four animated-style avatar palettes and cropped image uploads. Changing the local user ID or password requires the current password; credentials remain separate from workspace exports.

In Settings > Google connection, paste a Google OAuth **Web application client ID** ending in `.apps.googleusercontent.com` (the Cloud project name is not a client ID). Register the exact JavaScript origin, e.g. `http://localhost:8080`, enable Gmail API and Google Sheets API, and configure the Google consent screen/test users as required. Never paste a client secret. This public client ID is saved with workspace settings.

Meeting Studio's email composer has an Authorize Google & send via Gmail button. Every send requests account selection and consent for `gmail.send`, then waits for Gmail's message ID before reporting success. Google Sheets backup similarly requests `drive.file`; it creates readable data tabs and a chunked complete workspace snapshot. Restore reads that snapshot and asks before replacing workspace data. Local password hashes are excluded. Backups are manual snapshots, not automatic synchronization. Access tokens are held only during the action and never saved in browser storage.

The sign-in orbit uses saved product names. The 200K people chip is explicitly a growth goal illustration, not a measured audience count. Motion respects reduced-motion and an icon pause control.

Run `node verify-google.cjs` for mocked Gmail/OAuth/Sheets checks. Live Google sending and backups require a valid configured client ID and user authorization and are not covered by those mocks.

Vercel deployment
-----------------
`vercel.json` builds the 16 app assets into `public/` using `node build.cjs`. Only that directory is served as static content. `api/meeting-summary.js` supplies the optional AI endpoint; configure OPENAI_API_KEY and OPENAI_MODEL privately in Vercel if needed. Local formatting works without them. Run `node verify-deployment.cjs` after building.

Deploy this directory as an Other/framework-null project named product-growth-with-imtial. The connected account must have permission to create that project. Add the resulting HTTPS origin to the Google OAuth client's authorized JavaScript origins. Browser-local data on localhost does not move to the deployed origin automatically: export a JSON workspace backup from the old origin and restore it on the new one. Local account credentials remain separate.

Readable text, responsive layout and CSV exports
------------------------------------------------
All workspace routes include Download your data with dataset, product, inclusive start/end dates and an explicit include-undated toggle. Section-level Download CSV buttons reuse those filters. Exports cover products, six-section health, tasks, members, meetings, campaigns, winners, daily marketing/audience metrics, monthly budgets, resources, notes, KPI snapshots and non-secret workspace settings. Product/task/campaign ranges match by overlap; health/team use product dates. CSV includes UTF-8 BOM, quoted multiline fields and spreadsheet formula escaping. CSV is for analysis; use JSON or Sheets backups for restore.

The sign-in illustration uses the supplied image, with live onboarding, average product health, product names/scores, completed tasks and meeting counts layered over it. Saved daily metrics through today determine onboarding. Product labels scroll continuously, with reduced-motion support. Changes refresh on re-entry or browser storage events. Text is larger across the app; mobile controls use larger tap areas and 16px form text.

Run `node verify-exports.cjs` for date/product/CSV cases. Browser checks also exercise the portrait load, CSV form, invalid date ranges and mobile overflow.

Account screen fit and transparent portrait
-------------------------------------------
The account screen uses a transparent portrait cutout with no enclosing frame, border or shadow. Desktop retains the live portfolio cards; phone layouts use a compact portrait beside the heading so all sign-in and sign-up controls fit at normal zoom. Browser checks verify 320x568, 360x640, 375x667, 390x844, 768x1024, 1366x768 and 1440x900, plus an alpha-channel pixel check. Very small viewports, large text/zoom, validation errors and software keyboards can require normal scrolling rather than clipping controls.
